# メジャー更新警告コメントの書式と冪等性ルール

`scripts/editor.py` が挿入・更新・削除するコメントの正確な仕様。

## 書式

```ts
targetRevision: "10.3.3",
// ⚠ メジャーバージョン更新あり: "11.0.0" (要確認: リリースノート等でbreaking changeを確認してから手動更新すること)
```

- `targetRevision` の実際の値は変更しない（現状の動作を壊さないため）。
- 警告コメントは `targetRevision` プロパティの直後の行に、同じインデント幅で挿入する。
- マーカー文字列は `⚠ メジャーバージョン更新あり:` で固定。この文字列と直後の
  `"<バージョン>"` を正規表現 `^(?P<indent>[ \t]*)//\s*⚠ メジャーバージョン更新あり:\s*"(?P<ver>[^"]+)"`
  で検出し、既存コメントの有無・バージョンを判定する。

## 冪等性ルール（`plan_edits_for_site` の分岐）

| 今回判定された kind | 既存の警告コメント無し | 既存の警告コメント有り（同一バージョン） | 既存の警告コメント有り（異なるバージョン） |
| --- | --- | --- | --- |
| `major` | 新規挿入 | 何もしない（冪等） | 新しいバージョンで上書き |
| `patch` / `minor` | （関係なし）値を書き換え | 陳腐化したコメントを削除 | 陳腐化したコメントを削除 |
| `none` / `downgrade` | 何もしない | 削除（解消されたとみなす） | 削除 |
| `error`（フェッチ失敗） | 何もしない | **削除しない**（判断材料が無いため） | **削除しない** |

`error` のときにコメントを消さないのは、一時的なネットワーク障害でメジャー更新の
検出結果が失われる（＝更新が無かったことになる）事故を避けるため。次回 `resolve` が
成功したときに改めて正しい判定が行われる。

## Before/After 例

**新規メジャー検出（挿入）**

```diff
     targetRevision: "10.3.3",
+    // ⚠ メジャーバージョン更新あり: "11.0.0" (要確認: リリースノート等でbreaking changeを確認してから手動更新すること)
 });
```

**メジャー→さらに新しいメジャーが出た場合（上書き）**

```diff
     targetRevision: "10.3.3",
-    // ⚠ メジャーバージョン更新あり: "11.0.0" (要確認: リリースノート等でbreaking changeを確認してから手動更新すること)
+    // ⚠ メジャーバージョン更新あり: "12.0.0" (要確認: リリースノート等でbreaking changeを確認してから手動更新すること)
 });
```

**手動でメジャー更新を取り込んだ後（stale コメントの自動削除）**

```diff
-    targetRevision: "10.3.3",
-    // ⚠ メジャーバージョン更新あり: "11.0.0" (要確認: リリースノート等でbreaking changeを確認してから手動更新すること)
+    targetRevision: "11.0.0",
 });
```
